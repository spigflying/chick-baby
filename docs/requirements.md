## 1. 背景與目標

- 原型：純前端單人電子雞，復古像素風（彩色像素蛋殼 + Game Boy 四色綠螢幕），存檔在 localStorage（`schemaVersion: 3`）。
- 目標：**多人版**——每個使用者有自己的家與一隻寵物，可以拜訪別人、用自己的金幣幫別人餵食、和其他人在同一個畫面即時玩「小雞下樓梯」。
- 核心原則：**伺服器權威**。規則、數值、金幣全部由後端決定；網頁只負責顯示與送出操作。
- 每隻寵物、每個重要行為都**永久保存**，為之後的對戰與合體留資料。

## 4. 功能需求

### 4.1 寵物、物種與成長

- **孵化**：新寵物從蛋開始，**1 分鐘內孵化**（`eggSeconds` 預設 60）。蛋的期間狀態不衰減、不能做任何動作。
- **沒有結局階段**：孵化後只會透過能力值一直成長；唯一的結束方式是照顧不周而死亡。孵化後所有食物都可以吃；每個物種孵化後只有一種外型（含走路 2 幀、睡覺 1 幀）。
- **物種**（開局選擇，之後不能改）。物種定義放在 `packages/engine`，**新增物種 = 加一筆定義 + 精靈圖**：

  | 物種 | 傾向 | 初始 力量/速度/體力/體重 | 成長倍率 |
  |---|---|---|---|
  | 雞 | 平均 | 10 / 10 / 10 / 20 | 全部 ×1.0 |
  | 鴨 | 體力高 | 9 / 9 / 14 / 22 | 體力 ×1.3 |
  | 企鵝 | 速度快 | 9 / 14 / 10 / 22 | 速度 ×1.3 |
  | 恐龍 | 力量強 | 14 / 8 / 10 / 26 | 力量 ×1.3 |

  數值為【預設】。下樓梯的碰撞框所有物種一致。
- **狀態**：飽食 / 快樂 / 精力 / 清潔 / 健康，範圍 0–100，初始 80/80/80/100/100。以下所有「每分鐘」速率與機率都乘上 **`timeScale = 1/12`**，而且**只在開放時間內計算**（v1.2，§4.7）。本節的「分鐘」「實際時間」都是指開放時間：
  - 衰減：飽食 −0.8、快樂 −0.6、精力 −0.5、清潔 −0.4；睡覺時飽食 ×0.5、快樂 ×0.3、精力 +1200（v1.4，原 +2；× timeScale = 每實際分鐘 +100，0 → 100 約 1 分鐘），精力滿 100 自動醒。
  - **便便**（v1.1）：
    - **v1.3**：只在**餵食後**發生，每次餵食 **70%**【預設】機率便便 1 坨；不再隨時間便便，也沒有飽食門檻與間隔。自然上限同時 3 坨。
    - 例外：**玫瑰茶**喝完直接 +20 坨（不受自然上限，硬上限 23）。
    - 每坨每分鐘讓清潔再 −0.3（× timeScale）。
  - **餵食不會降低清潔**（v1.1，取消原型的 −4）。
  - **生病**（v1.1）：
    - 清潔 < 25 **持續 ≥ 30 分鐘**（實際時間，記在 `dirty_since`）後，才開始以每分鐘 5%（× timeScale）的機率生病。
    - 飽食 < 15 時，同樣每分鐘 5%（× timeScale）。
  - 健康：每項 < 20 的狀態每分鐘 −0.6，生病再 −0.8；全部正常且沒生病則 +0.3。
- **節奏**：在 `timeScale = 1/12` 下，模擬完全不照顧到死亡的中位數約 **26 小時（23–30 小時）的開放時間**。每個平日開放 11 小時，所以約 **2.4 個工作天**沒人照顧會死；晚上與週末不會餓死（v1.2）。
- **屋主動作**：餵食、睡覺（`sleep`，體力 +0.5）、起床（`wake`）、清潔（清潔 = 100、便便清空）、看醫生（解除生病、健康 +30、快樂 −10；健康 > 90 且沒生病時不用看）、下樓梯、看狀態。睡覺時只能起床。
- **能力值**：力量、速度、體力、體重（1–999）、性格（溫和 / 貪吃 / 活潑 / 懶散 / 勇敢 / 機靈，規則沿用原型）。
- **死亡**：健康 0 = **真的死亡**，記錄 `died_at` 與死因。屋主可以孵一隻新的；舊寵物保留為歷史紀錄。
- **永久保存、一人一隻**：每個使用者養過的每一隻寵物都永久保存（不刪除）；同時只能有一隻存活寵物（DB 部分唯一索引保證），資料模型保留一人多隻的可能。
- **管理員復活**：【預設】復活後健康 50、其他狀態 50、不生病、便便清空，能力值保留；若該使用者目前已有存活寵物則拒絕復活。

### 4.2 家與拜訪權限

- 每個使用者第一次登入時自動建立一個家，並取得一組**分享碼**。【預設】分享碼為 8 碼 Crockford Base32 隨機字串，使用者可以重新產生，舊碼隨即失效。
- 進入模式：

  | 模式 | 誰能進入 |
  |---|---|
  | `open`（**預設**） | 所有登入的使用者，**黑名單上的人除外** |
  | `invite_only` | 只有邀請名單上的人（黑名單仍優先） |
  | `closed` | 只有屋主 |

- **沒有公開的使用者目錄**（v1.1）。找到別人的家只有這幾種方式：
  - 輸入對方的分享碼，或打開分享連結 `/h/<分享碼>`
  - 「最近拜訪過的家」
  - 「邀請我的家」
- **邀請與黑名單**：屋主輸入對方的分享碼來加入邀請名單或黑名單；也可以從「來過 / 餵過我寵物的人」清單直接加入黑名單。撤銷前一直有效；屋主不在線時被邀請的人也能進入。
- 被加入黑名單或模式變更時，伺服器立即把不符資格的訪客移出房間。
- 進入家 = 加入該家的即時房間（WebSocket），看到寵物即時狀態、目前在場的人（顯示名稱）與其他人的動作。死亡寵物的家顯示墓碑。

### 4.3 餵食與錢包

- **錢包屬於使用者**；新使用者起始 **◎20**。價格固定，餵自己或別人的寵物一樣價錢：

  | 食物 | 價格 | 飽食 | 快樂 | 健康 | 體重 | 力量 | 速度 | 體力 | 訪客可餵 |
  |---|---|---|---|---|---|---|---|---|---|
  | 米粒 | 免費 | +20 | +2 | +1 | +1 | | | +0.5 | **否** |
  | 糖果（點心） | ◎3 | +5 | +20 | −3 | +2 | | +1 | | 是 |
  | 蟲蟲 | ◎5 | +20 | +8 | +3 | +1 | +4 | +1 | +1 | 是 |
  | 玉米 | ◎10 | +35 | +6 | +4 | +2 | +2 | +3 | +4 | 是 |
  | 蛋糕（點心） | ◎15 | +10 | +35 | −5 | +4 | +2 | | +2 | 是 |
  | 玫瑰茶（飲料・點心，v1.3） | ◎500 | +5 | +25 | +2 | | | | +1 | 是；喝完 **+20 坨便便** |

- **飽食限制**（所有人，包含屋主）：
  - 飽食 ≥ 90 → 只能吃點心
  - 飽食 = 100 → 全部拒絕
  - 寵物睡覺時不能餵
- **訪客規則**：
  - 只能餵付費食物（不能餵米粒）。
  - **低健康保護**：健康 < 30【預設】時，訪客不能餵點心。
  - 每日上限（Asia/Taipei 00:00 重置）：
    - 每隻寵物每天**所有訪客合計最多 20 次**
    - 同一位訪客對同一隻寵物每天最多 **5 次**
- **屋主**：餵自己的寵物**不計次、不限次**，只受飽食限制。
- **處理流程**：
  1. 前端送 `feed {pet_id, food_id, request_id}`。
  2. 伺服器在**單一 DB transaction** 內：
     - 檢查冪等鍵（§6）
     - 依固定順序鎖住錢包與寵物（§6）
     - 把寵物狀態結算到現在
     - 檢查權限、存活、睡覺、飽食、訪客規則、上限、餘額
     - 扣幣、更新寵物與計數，寫 ledger、事件、稽核
  3. Commit 後廣播結果。
  
  前端只播放動畫。

### 4.4 小雞下樓梯

#### 共通（M1）
- 玩法沿用原型：平台有 普通（踩到回 1 HP）/ 尖刺（−4 HP）/ 輸送帶 / 彈簧 / 易碎；頂端尖刺 −4 HP；HP 歸零或掉出畫面底部就出局。
- 能力影響：HP 上限 `10 + min(4, floor((體力−10)/5))`；移動速度 `1.2 + min(0.5, (速度−10)×0.03)` px/tick。
- **引擎**：TypeScript 共用套件 `packages/engine`，伺服器與前端跑同一份程式碼。決定性設計：30 tick/秒、seeded PRNG（例如 mulberry32）、不使用 `Math.random()`、不依賴實際時間。
- **伺服器權威模擬**：M1 的單人下樓梯也在伺服器上跑（1 人房間），並使用 §5 的輸入時間軸、時鐘同步與自身預測（沒有其他玩家，也沒有推擠）。
- 開始條件：精力 ≥ 15（原型的「太累了」門檻）；寵物存活且醒著。
- **結算**（v1.1：消耗量也乘上 timeScale）：
  - 精力 −15 × timeScale（≈ −1.25）、飽食 −8 × timeScale（≈ −0.67）
  - 快樂 +10+min(15, ⌊樓層/2⌋)
  - 速度 +min(2, 0.5+樓層×0.03)（乘以物種倍率）
  - 體重 −1
- **每日可玩回合數（估算，v1.2）**：每天 09:00 開門時精力回到 100（§4.7）；醒著時精力每小時 −2.5，一天 11 小時約 −27.5。每回合 −1.25，所以白天不睡覺時約可玩 **(100 − 15 − 27.5) ÷ 1.25 ≈ 46 回合/天**；白天讓寵物睡覺（v1.4：約 1 分鐘睡飽）可以再多玩。精力 100 時可以連續玩約 68 回合，直到降到 15。
- 單人獎勵：每下 1 樓 = **◎1**。

#### 多人（M2）
- 房間 2–6 人；開房 → 其他人輸入房間碼加入 → 房主開始；開始後不能中途加入。
- 所有人的寵物在**同一個畫面**、同一組平台；寵物之間有碰撞、會互相推擠，可以把別人推死。被誰推出局要記錄下來。
- 出局只影響該局，不扣寵物健康。
- 【預設】排名：依出局順序（越晚出局越前面）；剩 1 人時結束；最長 5 分鐘，時間到時依樓層排名。
- 【預設】獎勵：`◎5 + (人數 − 名次) × 3`，所有人都有保底；消耗與成長結算同單人。
- 【預設】場地邏輯寬 144px（單人 96px）。
- 細節見 §5。

### 4.5 金幣經濟

- 來源：起始 ◎20、單人下樓梯（1 樓 = ◎1）、多人下樓梯（保底 + 名次，M2）。
- 消耗：食物（◎3–15）。屋主可以無限餵免費米粒，所以沒錢不會讓寵物餓死；金幣主要用來買能力食物和幫別人餵食。
- 金幣**只能由伺服器在 DB transaction 中變動**，每筆都寫 `coin_ledger`；不能轉帳。
- 【預設】不設每日賺幣上限，用 ledger 觀察；`game_config` 預留 `dailyEarnCap`。

### 4.6 管理員功能

- 查看所有使用者（顯示名稱、id、分享碼、錢包；**不顯示 email**）、每個使用者的所有寵物（含死亡紀錄、能力值、事件歷史）。
- 復活死亡寵物（§4.1）。
- 所有管理動作都寫入稽核紀錄。
- 參數直接改 `game_config`；補幣/扣幣用管理指令，一定寫 ledger。

### 4.7 開放時間與夜間睡覺（v1.2）

- **開放時間**：週一到週五 **09:00–20:00**（Asia/Taipei），包含 09:00、不包含 20:00。其他時間（平日 20:00–翌日 09:00、週六日全天）是**休息時段**。
  - 【預設】國定假日、補班日不特別處理：只看星期幾。
  - 開放時間是**部署設定**（環境變數 `OPEN_HOURS`，例如 `mon-fri 09:00-20:00 Asia/Taipei`），不放 `game_config`，因為休息時段資料庫是關的。要改時間，必須同時改 Cloud Scheduler 的資料庫開關機排程（§8）。
- **休息時段整個遊戲關閉**：
  - 資料庫停機，所以**所有人（包含管理員）都不能登入、看狀態或做任何動作**。
  - 前端只顯示「小雞睡覺中 💤」畫面：所有寵物用睡覺圖、顯示下次開放時間與倒數。不建立 WebSocket，也不呼叫需要資料庫的 API。
  - 伺服器在資料庫停機時也要能啟動：只提供靜態前端、`/healthz` 與 `GET /status`（不碰資料庫）。migration 延後到第一次連上資料庫時才執行。
  - 休息時段收到需要資料庫的請求 → 回 `GAME_CLOSED`（附 `opens_at`）。
- **時間凍結**：
  - 寵物的模擬（`last_simulated_at` 補算到現在）**只累計開放時間**，休息時段不衰減、不便便、不生病、健康不變、不會自動醒。
  - 「實際時間」計時同樣只算開放時間：骯髒持續 30 分鐘（`dirty_since`）、蛋孵化 60 秒（`eggSeconds`）。例如 19:59:30 孵的蛋，在下個開放日 09:00:30 孵化。
  - 實作：引擎提供 `openSecondsBetween(a, b)` 之類的函式，把 `[a, b)` 中落在開放時間的部分切出來，依序模擬。必須是決定性的，並加測試（跨晚上、跨週末、剛好在 09:00 / 20:00 邊界）。
- **早安**：模擬每跨過一次「休息 → 開放」的邊界（平日 09:00），寵物就自動醒來（`sleeping = false`），【預設】**精力回到 100**，並寫入 `pet_events`（`wake`，payload `{reason: "morning"}`）。蛋與死亡寵物不適用。
- **關門流程**：
  - 19:55 起不能開始新的下樓梯；伺服器廣播 `game.closing {closes_at}`，前端顯示「5 分鐘後睡覺」。
  - 20:00 時，還在進行的下樓梯標記 `aborted`（不發獎勵、不扣精力，同 SIGTERM），伺服器廣播 `game.closed {opens_at}` 並關閉 WebSocket。前端切到睡覺畫面，**不自動重連**，等到開放時間再連。
  - 是否開放以**伺服器時間**判斷，並在寫入的 transaction 內檢查；20:00:00 之後的寫入一律拒絕。
- **每日上限**：訪客每日餵食上限仍以 Asia/Taipei 日期計（00:00 重置），休息時段本來就不能餵，不受影響。

### 4.8 拜訪同框與玫瑰茶（v1.3）
- **在場名單帶寵物**：`home.presence` 的每位使用者帶 `pet: {id, name, species, status, sleeping, sick, mood} | null`（`mood` 由快樂值換算 happy ≥ 60 / ok ≥ 30 / sad）。加入時伺服器從 DB 讀取，透過 `LISTEN/NOTIFY` 傳給所有執行個體；在場者自己的寵物狀態改變時（例如死亡、睡覺）也會更新所有拜訪中的家。
- **畫面**：蛋殼螢幕切成互不重疊的跑道，第 0 條給主人寵物（主人不在線上也照樣顯示，牠住在這裡），其餘依使用者 id 排序給訪客，所以每個人看到的順序一樣。訪客寵物在自己的跑道內慢慢走；最多顯示 **4** 隻訪客寵物，其餘以「+k」表示。每隻寵物頭上有小名牌（使用者名稱，主人名牌反白）。
  - 訪客沒有寵物：只顯示「名稱·沒寵物」名牌；寵物是蛋：畫蛋；死亡：畫幽靈並在名牌加 †；睡覺：閉眼加 Z；生病：骷髏。
  - 主人的動作與動畫（餵食、清潔、下樓梯）不受影響；下樓梯時隱藏名牌。
- **提示**：有人加入／離開時顯示「X 來了／X 離開了」並播放方波提示音（剛進家的第一份名單不提示，自己不提示）。
- **手機版**（寬 ≤ 640px）：「現在在這裡」移到蛋殼上方。
- **玫瑰茶**：◎500、飲料（算點心，飽食 ≥ 90 時仍可喝）、所有階段都可以喝；訪客也能買，照一般訪客規則（付費、每日上限、低健康不能喝點心）。伺服器權威：扣款寫入 `coin_ledger`（`reason = feed`），喝完立刻 +20 坨便便（記一筆 `poop` 事件，payload `count`）。前端動畫：杯子落下 → 寵物走過去小口啜飲 → 杯中茶水一格一格變少直到喝光（約 5 秒）。畫面上便便由右往左一排 16 坨，超過往上疊。

### 4.9 打架模式（v1.5）
- **誰能上場**：在這個家裡、寵物**活著、醒著、沒生病**的在線使用者（主人與訪客）。進家時自動加入場地；寵物睡著／生病／死亡或離開就退場（對戰中＝判輸）。主人不在線上時，他的寵物照常顯示但不能被打。黑名單原本就進不來。寵物跟著主人（主人外出中自己家不畫寵物，見下方）。
- **操作**（與下樓梯一致）：←→ 移動、↑ 跳、空白鍵 啄、↑＋空白（或「上啄」鈕）上啄、Z（或「道具」鈕）用道具、X 切換裝備的道具；手機用螢幕下方 ◀ ▲ 啄 上啄 道具 ▶；滑鼠左鍵按住往左、右鍵按住往右。
  - **有訪客時（含主人家）**：預設控制寵物；Enter（手機「選單」鈕）開啟動作列，方向鍵選、Enter 確定或 Esc 返回寵物控制。主人也看得到打架控制面板與按鍵提示。
  - **自己一個人**：方向鍵照舊選動作；只有正在對戰時才控制寵物。
- **攻擊**
  - **啄**：面向方向貼身＋**14px** 命中最近的一隻，傷害 **10**、擊退加大、冷卻 **0.5 秒**（要重新按）。每次揮擊畫白色「啄波」弧線約 **0.15 秒**（揮空也畫）。命中：目標白閃、飄出 `-N`、畫面微震；**沒有音效**。揮空只畫弧線。
  - **上啄**（↑＋空白／「上啄」鈕）：**一定會跳**（空中則小跳），只打頭頂正上方（沒有前方距離），傷害 10、冷卻 **0.8 秒**。目的是懲罰跳來跳去（空中很脆弱）。
  - **踩頭**：從上方踩中頭，傷害 **12**（原 15）、彈起。
  - 被打中後 **0.5 秒**無敵，精靈閃爍。快速點按（同一 tick 內按下又放開）也算一次。
- **蹬牆跳**：空中碰到左／右牆時落地變慢（牆滑）；按跳往反方向蹬開。每面牆只能蹬一次，落地或碰到另一面牆才重置。
- **開打（混戰）**：沒有在對戰的寵物第一次打中對方時，**場上所有合格寵物一起開打**（一場）。對戰中的寵物與第三者之間的攻擊一律忽略。限時 **1 分鐘**、各 100 對戰 HP（不影響真實狀態）。HP 到 0 → KO 觀戰（不能動、不能被打）。結束：剩 1 隻，或時間到 → 最高 HP 勝，並列最高＝平手。對戰中離開／睡覺／生病／死亡＝判輸。結束後 HP 回滿。
- **賭注**：每個輸家付 `min(20, 自己的餘額)` 給贏家；平手／取消不轉帳。單一 transaction：`fights` 該筆 `status = playing → done`（冪等，以對戰 id 為準）、依 user id 排序鎖所有參賽者的錢包、多筆 `coin_ledger`（`reason = fight`，`ref = fight id`）、一筆 `audit_log`（`fight.settle`）。`participants` jsonb 存每位的統計。
- **結算畫面**：決勝瞬間凍結模擬與畫面；每位參賽者看到彩帶橫幅（贏家寵物名（暱稱））＋自己的金幣變化（`+X`／`-X`）；輸家多一行「你輸了」與數據（造成傷害、命中、被打、剩餘 HP、損失金幣）；觀眾只看橫幅。點一下／按任意鍵／約 **6 秒**關閉。
- **防濫用**：同一家結束後約 **30 秒**內不能再開打（`HOME_COOLDOWN`）；伺服器限制輸入頻率（同下樓梯 ≤ 每秒 35 筆）。
- **開放時間**：快關門（19:55 起）或整場（1 分鐘）會超過關門時間時拒絕開打（`GAME_CLOSING`）；20:00 關門與 SIGTERM 時進行中的對戰取消、不轉帳（`fights.status = aborted`）。
- **道具**（動作列「道具店」；對戰外用金幣買；對戰中使用）
  - 庫存：`user_items (user_id, item_id, fights_left)`。買入走 `coin_ledger`（`reason = item`）、冪等 `request_id`、稽核 `item.buy`。對戰中不能買（`IN_FIGHT`）。
  - 使用：Z／「道具」鈕；X 切換裝備中的道具；HUD 顯示裝備中的道具＋剩餘場數。**每場有用到至少一次就在結算扣 1 場**（取消的對戰不扣）。
  - **長劍**（◎150／10 場）：揮砍約 **42px**、傷害 12、冷卻 0.7 秒，場內不限次。畫劍弧。
  - **龜派氣功**（◎300／5 場）：按住 1 秒蓄力（蓄力中不能移動、發光），面向方向橫射整場光束、傷害 30；**每場一次**。
  - **丟大便**（◎50／10 場）：拋物線投射物（受重力）、傷害 8、目標短暫滑倒。**v1.6.1：擁有就能在對戰中無限丟**，只受 0.5 秒（15 tick）冷卻限制；和地上的便便數無關，丟大便**不會**改變任何寵物的 `poop`、也不會廣播寵物更新。對戰中有用到照樣在結算扣 1 場（每場一次）。HUD 不顯示彈藥數。
- **伺服器權威 / 網路**：模擬在伺服器（30 tick/s，與下樓梯相同）。每個家由「目前有連線的最小執行個體 id」負責模擬；輸入（`arena.join` / `arena.input` / `arena.leave`）與狀態（`arena.state`，有變化時每 3 tick 一次、否則每 2 秒心跳）都經過 `LISTEN/NOTIFY`。負責的執行個體換人時，進行中的對戰取消（不轉帳），客戶端自動重新加入。客戶端在快照之間插值，沒有本地預測。
- **寵物跟著主人**：一隻寵物同時只在一個地方——主人在哪裡牠就在哪裡。主人正在別人家（而且沒有任何分頁在自己家）時，自己家不畫寵物，只顯示「主人外出中」（為了隱私不透露在誰家），訪客也不能餵；主人在自己家或離線時寵物在家。主人不會出現在自己家的「現在在這裡」。`home.presence` 多帶 `owner_away`。在場名單每 30 秒心跳、75 秒沒刷新就移除。打架場地同規則。
- **名稱**：畫面上寵物名牌用**主人取的寵物名**（`pets.name`），滑過顯示主人暱稱；人名一律用使用者自訂的**暱稱** `users.display_name`；對戰 toast／結算橫幅顯示「寵物名（暱稱）」。
- **畫面**：對戰中的寵物頭上有 HP 條、畫面上方顯示剩餘秒數；開打「…混戰開打！」、結束走結算畫面。
- **參數**（`ARENA_PARAMS`）：HP 100、啄 10／距 14px／冷卻 15 tick／啄波動畫約 0.15s、上啄 10／冷卻 24 tick、踩 12、擊退 4.5、無敵 15 tick、移動 1.2px/tick、跳躍初速 −3.6、重力 0.25、牆滑最大落速 0.8、蹬牆初速 (−3.4, ±3.2)、限時 1800 tick、家冷卻 30 秒、場上最多 8 隻、賭注上限 ◎20、長劍 42px／12／21 tick、龜派氣功蓄力 30 tick／30、丟大便 8／滑倒 20 tick。


### 4.10 發起戰鬥、獎池與排行榜（v1.6）
- 開打方式：只有「發起戰鬥」（按鈕／F）能開打；對戰外的攻擊不造成傷害、不擊退。同一個家同時只能有一個邀請或一場對戰（`FIGHT_BUSY`）。
- 邀請：`arena.invite` → 廣播 `arena.event{kind:'invite', invite, from, from_name, to[], left_ms:10000}`；被邀請者回 `arena.reply{invite, accept}`（`kind:'reply'` 廣播）。10 秒到或所有人都回覆就決定：發起人＋接受者中仍在場且合格的人，≥2 → `start`，否則 `kind:'invite_cancel'`（`NOT_ENOUGH` 或 `canStart` 的原因）。
- 在別人家發起需要主人在家（不是外出中、不是離線），且主人的寵物醒著、沒生病：`OWNER_AWAY`／`OWNER_OFFLINE`／`OWNER_SLEEPING`／`OWNER_SICK`。快照多了 `cooldown_ms` 與 `invite`。
- 結算：贏家拿輸家的 min(20, 餘額)（平手不轉帳）；獎池 50 依總傷害按比例、最大餘數法分配（同餘數依 user id），reason `fight_bonus`。結果訊息每人有 `transfer`、`pool`、`delta`（＝transfer＋pool）。
- 結算畫面：鎖 3 秒 → 可關閉，8 秒自動關；排名依分數由高到低。
- 排行榜 API：`GET /api/leaderboard/stairs` → `{ top: [{rank, pet_name, owner_name, species, best_floor, mine}] (最多 10), me: {pet_name, best_floor, rank} | null }`；只含 best_floor > 0 的寵物、不含 email。

## 5. M2 網路同步規格（草案，M2 開工前定案）

> 單人模式（M1）先實作其中的時鐘同步、輸入緩衝與自身預測；M2 再加上推擠、他人插值與推擠校正。

### 5.1 推擠物理（公式草案）
- 參數：
  - 推力 `P = clamp(1 + (力量 − 10) / 50, 0.8, 1.6)`
  - 質量 `M = clamp(1 + (體重 − 20) / 50, 0.8, 1.6)`
- 碰撞條件：兩隻碰撞框水平重疊 `d > 0`，而且垂直重疊 ≥ 3px。v1 只處理水平推擠；落到別人頭上時往旁邊滑開，不能疊站。
- 驅動值：`a = P × (正朝對方移動 ? 1 : 0.5)`（站著不動也有一點抵抗力）。
- **位置分離**：
  - 先算 `wA = a_A / M_B`、`wB = a_B / M_A`。
  - B 往 A 的移動方向被推開 `d × wA / (wA + wB)`，A 往反方向退開其餘距離。
  - 雙方同時對推、數值相同時互相抵消。
- **推擠速度**：
  - B 加上 `pushVx += dirA × 0.5 × P_A / M_B`，`|pushVx|` 上限 2.0 px/tick，每 tick 衰減 ×0.85。
  - `pushVx` 疊加在一般移動上，空中也有效，所以可以把人撞下平台。
- **擊殺歸屬**：出局前 60 tick（2 秒）內最後一個推過該寵物的人，記為 `eliminated_by`。
- 處理順序固定：依 `pet_id` 排序，兩兩處理，確保結果是決定性的。

### 5.2 時鐘同步
- 連線後送 5 次 `time.ping {t0}`，伺服器回 `time.pong {t0, serverTime, serverTick}`。
- `rtt = now − t0`、`offset = serverTime + rtt/2 − now`；取 rtt 最低的幾筆的中位數。比賽中每 10 秒重新同步一次，offset 平滑調整、不跳變。
- 客戶端用 offset 推算「目前伺服器 tick」。

### 5.3 輸入（標記 tick + 緩衝 N tick）
- 客戶端只送左右按鍵，在按鍵狀態改變時送出 `match.input {seq, tick, left, right}`，其中 `tick = 估算伺服器 tick + N`。伺服器沿用最後一筆輸入，直到下一筆。
- 【預設】`N = 3`（100ms），依抖動自動在 2–6 之間調整。
- 伺服器在指定的 tick 套用輸入：
  - 遲到（tick ≤ 目前 tick）→ 在下一個 tick 套用，並回報 `late`，讓客戶端加大 N。
  - 超前太多（> 目前 tick + N + 15）→ 拒絕。
  - `seq` 必須遞增。

### 5.4 預測、插值與校正
- **自己**：用共用引擎立即模擬（預測），保留還沒被確認的輸入。
  - 收到快照時，以伺服器狀態（含 `lastProcessedSeq`）為準，重設自己的狀態後，重新套用尚未確認的輸入。
  - 誤差 ≤ 8px 時，畫面在 100–150ms 內平滑修正；超過就直接瞬移。
- **其他人**：用插值顯示，延後約 100ms（兩個快照之間）。
- **快照**：每 2 tick 一次（15 次/秒），內容是每位玩家的 `x, y, vx, vy, pushVx, hp, floor, alive` 加上平台狀態變化（易碎等）。
- **已知問題：推擠校正**。自己顯示在「未來」，其他人顯示在「過去」，所以本地預測的碰撞和伺服器結果會不一致，被推或推人時畫面會被拉回。
  - 【預設】對策：
    - 客戶端**不預測與他人的碰撞**，推擠只由伺服器決定，透過校正平滑呈現。
    - 伺服器另外送 `match.pushed` 事件，讓客戶端播放撞擊動畫。
  - 代價：被推的反應約延遲一個 RTT。M2 實測後再評估是否預測推擠。

### 5.5 `match.started` 內容
- `seed`、`engine_version`、`config_hash`、`start_tick`、`server_time_at_start`。
- **完整遊戲參數**：
  - `tickRate`、`snapshotEvery`、`inputBufferTicks`
  - 場地寬高
  - 重力、最大落下速度、彈簧速度、輸送帶速度、捲動速度公式參數
  - 平台寬度與間距、平台種類機率
  - HP / 速度公式參數、推擠參數
  - `matchMaxTicks`、獎勵參數
- **玩家清單**：user id、顯示名稱、pet_id、物種、能力值、出生位置。
- 客戶端的 `engine_version` 和伺服器不同時要拒絕開始並重新載入。參數全部由伺服器下發，客戶端不寫死。

## 6. 伺服器權威與防作弊

- 前端**只送操作意圖**（`feed`、`clean`、`sleep`、`wake`、`doctor`、下樓梯左右輸入），不送數值結果。狀態衰減、隨機事件都在伺服器計算，亂數在伺服器端產生。
- 下樓梯完全在伺服器模擬；輸入要驗證格式、頻率與 seq。
- 每個動作都在伺服器重新檢查權限，不信任前端狀態。
- **冪等**（v1.1）：
  - 所有會改變資料的動作（REST 與 WS；不含 `match.input`，它用 seq）都帶 `request_id`（UUID）。`request_id` 只要求**在同一個使用者內唯一**。
  - 在同一 transaction 內寫入 `idempotency_keys`，主鍵 `(user_id, request_id)`。
  - 重複請求時：
    - 內容雜湊相同 → 回傳上次存下的結果
    - 內容雜湊不同 → `409 IDEMPOTENCY_CONFLICT`
  - 【預設】保留 7 天。
- **上鎖順序**（v1.1）：transaction 內固定先鎖錢包、再鎖寵物，同類依 id 排序。
  - 例：`SELECT … WHERE user_id = ANY($1) ORDER BY user_id FOR UPDATE`
  - 例：多人比賽結算時，所有玩家的錢包排序後一起鎖，再依序鎖寵物，避免死結。
- **離線衰減**：【預設】存取時結算——每次讀取或寫入寵物時，依 `last_simulated_at` 補算到現在，然後寫回。
- **不依賴單一執行個體確保正確性**：所有規則與計數都以 DB 為準（transaction、唯一索引、上鎖）。記憶體中的頻率限制只是近似防護，不影響正確性。

## 8. 技術架構

```
瀏覽器（apps/web：TypeScript，Canvas 像素 UI）
   │ HTTPS (REST)          │ WSS (家的房間、下樓梯)
   ▼                       ▼
Cloud Run（apps/server：Node.js + TypeScript，REST + WS + 遊戲迴圈 + 靜態前端）
   │ Cloud SQL Node.js Connector          ▲ LISTEN/NOTIFY（跨執行個體廣播）
   ▼                                      │
Cloud SQL for PostgreSQL ─────────────────┘
```

- **Repo**：`spigflying/chick-baby` monorepo，包含 `apps/web`、`apps/server`、`packages/engine`；根目錄原型與 GitHub Pages 不動。
- 【預設】技術選型：Node.js 22 LTS、pnpm workspaces、Vite、Fastify + `ws`、Kysely 或 Drizzle + SQL migration、Vitest（引擎要有決定性測試：同 seed + 同輸入 → 同結果）。
- **GCP**：專案 `silver-greens`（編號 704427759894）；【預設】區域 `asia-east1`。
- **Cloud Run（v1.1）**
  - **正確性不依賴單一執行個體**。官方文件：「this maximum setting can be exceeded for a brief period due to circumstances such as traffic spikes」（max instances 可能短暫被超過）。
    - 設定（v1.2，見 `DEPLOY.md`）：`min-instances=0`、`max-instances=2`（Cloud SQL f1-micro 只有 25 條連線）、instance-based billing（遊戲迴圈不被節流），request timeout 3600 秒，開啟 session affinity，concurrency 1000。
  - **跨執行個體廣播**：寫入 commit 後 `NOTIFY`（channel 例如 `home_<id>`、`user_<id>`，payload 只放 id 與事件類型），每個執行個體 `LISTEN` 後再推送給自己的 WS 連線。需要一條專用的長連線（不放在連線池裡）。
  - **比賽房間**：一場比賽只在一個執行個體上跑，`stair_matches.instance_id` 記錄是哪一個。
    - 玩家的連線落在其他執行個體時，`match.join` 回 `WRONG_INSTANCE`，客戶端重連再試（session affinity 會盡量導回同一個），最多 5 次。
  - **主動重連**：
    - WS 連線存在約 **50 分鐘**時，客戶端在**不在比賽中**的時機主動重連。
    - 比賽開始前，伺服器檢查每位玩家的連線時間；超過 45 分鐘的人先重連，才開始比賽（比賽最長 5 分鐘，一定能在 60 分鐘上限前結束）。
  - **SIGTERM**：Cloud Run 關閉前約有 10 秒。伺服器廣播 `server.draining` 請客戶端重連到其他執行個體，進行中的比賽標記 `aborted`（不發獎勵、不扣精力），然後關閉連線。
- **Cloud SQL**：PostgreSQL 16（`db-f1-micro`）；連線池；每日自動備份與時間點復原。**只在平日開機**（v1.2）：08:45 開機、20:15 關機，前後各留 15 分鐘給開機與收尾。自動備份時段要在開機期間（【預設】台北 12:00）。
- **登入**：Google Identity Services ID token → `POST /auth/google` → session。不限網域；OAuth 同意畫面為 External，scope 只用 `openid email profile`，並發布到正式版。
- **排程**（Cloud Scheduler，共 3 個 job，在每個帳單帳戶 3 個免費 job 以內）：
  - `chick-db-start`：平日 08:45，透過 SQL Admin API 把 `chick-db` 的 activation policy 設為 `ALWAYS`。
  - `chick-daily`：平日 20:05（關門後、資料庫關機前），呼叫內部端點，清除 30 天前的稽核 IP、7 天前的冪等紀錄與過期 session。
  - `chick-db-stop`：平日 20:15，activation policy 設為 `NEVER`。
